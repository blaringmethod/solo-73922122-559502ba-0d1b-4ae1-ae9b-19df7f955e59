# 疾控汇总发布安全审查台

疾控数据员在公开「分区 × 年龄组」汇总检出数前，用本工具审查：**多份已公开汇总叠加后，是否会暴露小样本格（原检出数 1~4）的取值**。技术栈：FastAPI + SQLite + z3-solver。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
```

访问：
- 内部审查台：http://localhost:8000/
- 公开页：http://localhost:8000/public

SQLite 库文件保存在命名卷 `app_data`（容器内 `/data/app.db`），重启后公开记录与报送对账保留。

### 本地运行

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

库文件默认在 `./data/app.db`，可用环境变量 `DB_PATH` 覆盖。

### 自测

```bash
.venv/bin/python tests/selftest.py                 # 32 项：调查导入与发布安全审查
.venv/bin/python tests/reconciliation_selftest.py  # 60 项：报送补正/作废与对账
```

## 演示流程（内置示例数据）

示例数据（`sample_survey.csv`，2 分区 × 2 年龄组，人数均 10）：

| 分区 | 年龄组 | 人数 | 检出数 |
|---|---|---|---|
| 城东 | 青年 | 10 | **2**（受保护小样本格） |
| 城东 | 老年 | 10 | 8 |
| 城西 | 青年 | 10 | 8 |
| 城西 | 老年 | 10 | 8 |

1. 打开内部台 `/`，点「导入示例数据」（导入后不可更换）。
2. 勾选「城东」+ 两个年龄组 → 预览（总数 10，安全）→ 确认发布。
3. 勾选两个分区 +「老年」→ 预览（总数 16）：单独看本安全，但与已发布的「城东」合并后，
   格「城东/青年」被约束到 **[0, 4]**（`城东合计10 − 城东老年≤10 ⇒ 城东青年≤4`，
   且 `老年合计16 ⇒ 城东老年≥6 ⇒ 城东青年≤4`），不再保留「≥5」的可行解 → 审查不通过。
4. 点「确认发布」→ 按最新公开记录重核，返回 409 并列出受影响格与可行范围。
5. 改发「青年」（总数 10）：与已公开记录合并仍安全 → 发布成功。
6. 打开公开页 `/public`：只有人数表与获准汇总，无格内检出数。
7. 在内部台第 5 节上传报送 CSV（或点示例按钮），查看逐格对账、差额、额外组合与批次审计。

## 安全模型

- 未知量：每格一个整数 `x_i`，约束**仅**来自
  1. 界限 `0 ≤ x_i ≤ 人数_i`；
  2. 历次公开记录：所选交集格之和 = 公开总数；
  3. 候选发布：所选交集格之和 = 候选总数。
- 判定：对每个原检出数为 1~4 的格，须同时存在 `x_i = 0` 与 `x_i ≥ 5` 的可行整数解，
  否则拒绝并给出该格可行范围（z3 Optimize 求 min/max）。
- 确认发布时在全局发布锁内**重读最新公开记录并重核**，随后单事务写入：
  两个各自安全、合并不安全的窗口不会都被发布；保存失败整体回滚，不留半次发布。
- 求解在工作线程执行（每评估独立 z3 Context，线程安全），求解期间公开页与其他发布可用。

## 报送补正 / 作废对账

各报送单位会分批上传补正与作废。内部台第 5 节提供上传与对账，公开页不出现上报明细。

CSV 表头：`报送ID,修订号,分区,年龄组,人数,检出数,作废标记`。

| 字段 | 规则 |
|---|---|
| 报送ID | 非空逻辑标识；同一 ID 可有多版修订 |
| 修订号 | 正整数 |
| 人数 / 检出数 | 整数；有效记录须满足 `0 ≤ 检出数 ≤ 人数` |
| 作废标记 | `是/否`、`1/0`、`true/false`，留空视为否 |

汇总规则：

- 每个 ID **只以最高修订**贡献汇总。更高修订若改了归属，先从旧格扣除再计入新格。
- 作废版成为该 ID 的最高修订时，撤去它的全部贡献；之后迟到重传旧版不复活。
- 同（ID, 修订号）内容完全相同的重传是幂等的，不重复计数；
  同（ID, 修订号）内容冲突、或任一行非法（含修订号非正、检出数越界）→ **整批拒收**，旧结果不变。
- 每批在一个 SQLite 写事务内落库；拒收/保存失败整体回滚，不留批次记录。
- 对账接口在同一个读事务中取有效报送、批次与固定调查格，逐格汇总与合计差额必然对应同一批已提交记录；
  不在调查格内的组合单列为「额外组合」，不并入调查格汇总。
- 调查格与已公开汇总不受报送影响；报送明细只出现在内部台与 `/api/reconciliation`。

示例：先导演示调查，再依次「导入示例报送」「导入示例补正批次」（`sample_submissions.csv`、
`sample_submissions_corrections.csv`），可看到 S001 改归属（城东/青年 → 城西/老年）、
S002 作废、S003 幂等重传、S004 额外组合单列。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/import` | 导入调查 CSV（multipart，仅一次，导入后不可更换） |
| GET | `/api/admin/state` | 内部状态（含格内检出数） |
| POST | `/api/preview` | `{districts, age_groups}` → 交集总数 + 安全评估 |
| POST | `/api/publish` | 重核后发布；不安全返回 409 + 受影响格与可行范围 |
| POST | `/api/submissions/import` | 上传报送补正/作废 CSV（multipart）；非法或冲突整批拒收 |
| GET | `/api/reconciliation` | 逐格汇总、相对调查差额、额外组合、有效报送与批次审计 |
| GET | `/api/public` | 公开数据：仅人数与获准汇总（不含上报明细） |

CSV 表头：`分区,年龄组,人数,检出数`（亦兼容 `district,age_group,population,detected`）。
校验：≤16 格；人数 ≥5；检出数为 0~人数整数；（分区,年龄组）唯一。

## 已知限制

- 未实现认证/授权：内部台与接口对任何可达者开放，生产部署须自行加访问控制。
- 发布串行锁为单进程内锁；多副本部署需改为数据库级互斥（如 SQLite 单写已天然串行，但重核-写入的临界区需以事务或文件锁保证）。
  报送上传与对账读写已使用数据库事务 + `BEGIN IMMEDIATE`，不依赖进程内锁。
- 审查基于精确整数可行域（z3），非差分隐私；它保证「小样本格不被公开信息钉死」，不量化其他泄露渠道。
- 报送对账只做算术核对（逐格汇总与差额），不校验各单位人数口径是否一致；额外组合单列供人工判断。
- 本环境未安装 Docker，`docker compose` 未在此实际构建运行；已用同一 `uvicorn app.main:app`
  启动命令与本地库文件验证启动、上传、对账及重启后数据保留。
